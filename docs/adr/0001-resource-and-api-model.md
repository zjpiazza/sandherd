# ADR 0001: Resource and API model

- Status: Accepted
- Date: 2026-07-29
- Owners: Sandherd maintainers
- Related issue: [#1](https://github.com/zjpiazza/sandherd/issues/1)

## Context

Sandherd runs persistent coding agents in Kubernetes Agent Sandbox workloads while presenting a client-neutral API. Herdr is the first interactive client, but the platform must also support command-line tools, web applications, IDEs, and automation.

Three lifetimes must not be conflated:

1. An **Agent** is the durable logical session requested by a user.
2. A **Sandbox** is the isolated Kubernetes execution environment assigned to that agent.
3. An **Attachment** is a temporary terminal connection to the agent process.

In particular, an attachment disconnect must not terminate the agent or delete its sandbox.

## Decision

### The public boundary is the Sandherd API

Clients use versioned REST, server-sent lifecycle events, and a versioned WebSocket terminal protocol. Kubernetes resource names, Pod addresses, Agent Sandbox router headers, service-account credentials, and internal bearer tokens are not public API.

The control plane is the only component that requires Kubernetes credentials. Herdr and other clients receive Sandherd credentials only.

### Durable state is represented by a Sandherd Agent CRD

The control plane persists desired and observed state in an internal `Agent` custom resource under `sandherd.dev`. A controller reconciles each Agent to exactly one Agent Sandbox `SandboxClaim` in the MVP.

This CRD is an implementation contract between Sandherd components, not the supported end-user API. Users are expected to use the REST API. Direct CRD mutation may bypass validation, authorization, and compatibility behavior supplied by the service.

The alternative of storing Sandherd state only in annotations on `SandboxClaim` was rejected because it cannot cleanly represent lifecycle intent, ownership, API versioning, terminal metadata, or failure state independent of the underlying sandbox.

An external database was rejected for the MVP because Kubernetes already supplies durable desired state, watches, optimistic concurrency, and reconciliation primitives. This decision can be revisited if multi-cluster placement requires a control plane above individual clusters.

### Identifiers and names

- Public agent IDs are UUIDv7 strings generated by the service. Clients treat them as opaque.
- Agent names are user-visible DNS-label-compatible strings, unique per owner, between 1 and 63 characters.
- Kubernetes names are derived independently and must not be reconstructed by clients.
- Attachment IDs and controller lease IDs are opaque UUIDs with shorter lifetimes than the agent.

### Agent state machine

The public states are:

```text
requested -> provisioning -> starting -> running
                  |             |          |
                  +-----------> failed <---+

running -> stopping -> stopped -> provisioning -> starting -> running
   |          |          |
   |          +-------> failed
   |
   +------------------------------> deleting -> deleted

failed ---------------------------> deleting -> deleted
stopped --------------------------> deleting -> deleted
```

`deleted` is observable through lifecycle events but is not returned as a live Agent resource after deletion completes.

Invalid transitions return `invalid_state_transition`. Reconciliation may retry internal operations without exposing additional transient states.

### Stop, resume, and delete semantics

- **Stop** gracefully terminates the agent process, preserves the logical Agent and workspace, and requests sandbox suspension after the runner has stopped. Stop is idempotent.
- **Resume** restores compute when necessary and starts the agent process using its durable workspace and supported native agent session reference. Resume is idempotent.
- **Delete** terminates the process and removes the sandbox. Workspace handling follows the Agent's `workspace.retentionPolicy`: `delete` removes the PVC; `retain` leaves it for explicit administrative recovery.

Stop is never inferred from a terminal disconnect.

### Idempotency and concurrency

- `POST /v1alpha1/agents` requires an `Idempotency-Key`. The service stores the key with the owner and canonical request hash. Repeating the same request returns the original Agent; reusing the key with a different request returns `idempotency_conflict`.
- Every Agent response includes an `ETag` derived from its resource version.
- Stop, resume, and delete accept `If-Match`. A stale value returns `precondition_failed` rather than overwriting newer intent.
- Request IDs are returned in `X-Request-ID` and in error bodies.

### Terminal attachment model

An agent has at most one active **control** attachment and any number of **observe** attachments.

- A controller may send input, resize the PTY, acknowledge output, and request explicit takeover.
- An observer receives replay and live output but cannot mutate the terminal.
- A control lease is issued only after an attachment succeeds. Mutating frames carry that lease ID.
- A takeover atomically revokes the previous lease and notifies the previous controller.
- Output receives a monotonically increasing sequence number within one runner process generation.
- Clients reconnect with the last contiguous sequence they processed. The runner returns subsequent buffered output followed by live output.
- If the requested sequence has fallen outside the bounded replay buffer, the server emits `replay_gap` with the earliest available sequence before continuing.
- Slow consumers are disconnected with a protocol error rather than creating unbounded buffers.

The terminal protocol transports bytes as base64. It does not assume UTF-8 and does not persist a permanent transcript.

### Authentication and authorization hooks

REST, SSE, and WebSocket operations require the same bearer authentication boundary. The initial identity provider is selected in a later security issue, but the contract requires an authenticated principal for every operation.

Authorization is evaluated against Agent ownership and requested attachment role. Internal router and runner credentials are short-lived, audience-restricted, and never returned to clients.

### Errors

All HTTP errors use one envelope:

```json
{
  "error": {
    "code": "invalid_state_transition",
    "message": "agent is already stopped",
    "requestId": "019c...",
    "retryable": false,
    "details": {}
  }
}
```

Messages are safe for humans but are not stable API. Clients branch on `code` and HTTP status. Terminal errors use the same code vocabulary in an `error` frame.

### Versioning

- REST versions are explicit URL prefixes such as `/v1alpha1`.
- Terminal clients offer the `sandherd.terminal.v1alpha1` WebSocket subprotocol and include `protocolVersion: "v1alpha1"` in the initial attach frame.
- Additive optional fields and new error codes may be introduced within a version.
- Existing field meanings, required fields, enum values that alter behavior, and frame semantics are not changed incompatibly within a version.
- Breaking changes receive a new REST version and terminal subprotocol.
- Clients ignore unknown object fields but reject unknown terminal frame types to avoid unsafe stream interpretation.

## Consequences

### Positive

- Herdr remains replaceable and does not need cluster credentials.
- Agent, sandbox, and attachment lifetimes are explicit.
- Controller restart recovery follows Kubernetes reconciliation patterns.
- Terminal reconnect behavior can be tested independently of any UI.

### Costs

- Sandherd must maintain a CRD in addition to Agent Sandbox resources.
- The gateway and runner need a lease and replay protocol rather than a simple attached `kubectl exec` stream.
- Multi-cluster orchestration will require a future layer above cluster-local CRDs.

## Rejected alternatives

### Herdr talks directly to Kubernetes

Rejected because it would make Herdr the platform boundary, distribute cluster credentials to clients, and prevent other integrations from sharing policy and lifecycle behavior.

### One Tailscale identity per agent

Rejected because it expands tailnet identity lifecycle and gives untrusted sandbox workloads unnecessary proximity to the private network. Only the Sandherd service is exposed; sandboxes remain internal.

### `kubectl exec` owns the agent process

Rejected because loss of the exec stream can terminate or orphan the foreground process and cannot provide reliable replay or multi-observer semantics. The runner owns the PTY instead.

### One Herdr server inside every sandbox

Rejected as the primary model because it fragments the unified agent view and couples the runtime to one client. It may remain useful as a debugging option.
